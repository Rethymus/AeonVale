# 《Aeon Vale: Song of the Dao》设计基线 (Design Brief)

> 本文件是整个设计文档包的**宪法**。所有后续文档、所有 agent、所有 vibe-coding 实现都必须遵循此处的愿景、核心循环、术语与约束。
> 一切内容为**设计/规格**，不含游戏实现源码。

---

## 0. 元信息

- **游戏名**：Aeon Vale: Song of the Dao（永恒山谷：大道之歌；内部代号 / 民间别称：《偷天劫》）
- **品类**：2D 修仙 · 种田模拟 · 炼丹解谜 · 天劫塔防生存（混合节奏）
- **灵感坐标**：星露谷物语（Stardew Valley，种田/季节/节奏）× 杀戮尖塔/Understand（系统涌现与策略）× 修仙小说套路（凡人流、天劫、炼丹）× 植物大战僵尸/王国保卫战（塔防生存片段）
- **平台目标**：离线单机、多端同核。当前以浏览器作为开发、测试与公开展示载体；后续通过桌面端封装优先支持 Windows 与 Linux，Android 等移动端后置评估；纯代码、不依赖 Unity/Cocos/Unreal 等通用游戏引擎。
- **开发范式**：Vibe Coding（AI 辅助从设计到代码），全程无人为干预，需可**自动化调试与测试**。
- **受众与基调**：东方仙侠美学；主题是「无灵根凡人在没落体修与天道夹缝中逆天改命」的挣扎感与逆袭快感；带黑色幽默与宿命感。

## 1. 一句话愿景

> **你是一个没有灵根的凡人。灵修之路对你关闭，没落的体修之路只剩残卷、苦练与天劫。种田是为了炼丹，炼丹是为了淬体，淬体是为了主动引劫——最终以凡骨与天道对弈、逆天改命。**

---

## 2. 核心体验目标 / 设计支柱 (Design Pillars)

1. **凡人的脆弱 (Mortal Fragility)** —— 玩家开局始终是蝼蚁：吃错灵草会中毒暴毙、被天雷擦边即重伤、大势不可逆。失败惩罚真实但可学习。
2. **体修的苦与狠 (Body-Cultivation Grit)** —— 灵修看灵根天资，体修靠苦练、意志、心智和资源。主角的绝灵之体实为**漏斗体质**（灵气吸收最强但全漏，详见 `03` §2.2.1），每一点体魄都来自重复训练、丹药淬体与濒死雷劫——天劫封堵漏洞，种田最大化灵气吞吐量，炼丹临时封堵，控血压力淬炼。
3. **逆天引劫的快感 (Tribulation-Defying Thrill)** —— 每一次主动引劫、以凡人之躯扛过天罚、把天道清算变成肉身资粮，都是高风险高回报的赌博。
4. **慢与快的张力 (Slow/Fast Tension)** —— 90% 时间是治愈向的慢种田/炼丹/基础苦练，10% 是天劫降临瞬间的极限塔防生存。两者用同一个场地（你的农庄）联结。
5. **系统涌现 (Emergent Systems)** —— 炼丹非线性的药性相克、天雷与灵草/阵法的物理交互、天象大事件的因果链，鼓励玩家自主发现解法，而非线性配方。
6. **东方仙侠美学与留白 (Xianxia Aesthetics)** —— 程序化/极简美术、留白、水墨/丹青意象、雷劫的视听冲击。
7. **可自动化验证 (Automatable)** —— 数值、随机、经济全部确定性可调参；存在无头模拟与平衡自动调参通路，支撑无人干预开发。

## 3. 核心循环 (Core Loop)

```
        ┌─────────── 种田(Farm) ───────────┐
        │  种灵草 → 灵气生长 → 收获/守田        │
        ▼                                    │
   炼丹(Alchemy) ◄──── 丹毒风险(凡骨不能生食) │
        │  投料 → 控火候 → 平衡药性 → 淬体丹   │
        ▼                                    │
   苦练(Training) : 百俯卧/百仰卧/百蹲/长跑 + 丹药淬体
        ▼                                    │
   主动引劫(Invoke Tribulation) ─────────────┘
        │  引劫/倒计时归零 → 切入「塔防生存」
        ▼
   硬抗天劫(Endure) : 近身硬抗 / 阵法控场 / 硬扛几雷淬体 / 控血
        │
        ▼
   突破(Breakthrough) : 劫雷淬体推进肉身境界，延长大限
        │
        ▼
   下一阶段，更强天劫 … 直至终极紫雷劫 → 飞升(通关)
```

**张力公式**：*慢节奏积累安全感 → 寿元/大限与引劫准备制造焦虑 → 塔防生存制造肾上腺素 → 突破制造多巴胺 → 回到慢节奏（但更强，也更被天道记账）。*

贯穿全程的干扰层：**动态天象奇遇**（喜/悲/危/机）随机调制整个循环。

## 4. 四幕主线（骨架，详见 02-narrative-bible.md）

| 幕 | 名称 | 一句话 | 核心玩法引入 |
|----|------|--------|--------------|
| 序章 | **幻灭期** Disillusionment | 穿越者求"系统/老爷爷"无果，被测为「绝灵之体」，扫地出门，回破村认命种地 | 教程：基础种田（凡间作物，无灵气） |
| 第一幕 | **转折期** Turning Point | 两修士斗法毁屋；败者化为灰，遗留受损储物戒；凡人意外抹去神识开启 | 获得：灵草种子、残缺丹谱、《偷天换劫诀》雷劫炼体残卷 |
| 第二幕 | **淬劫期** Tribulation-Tempering（游戏核心循环） | 苦练打底、丹药淬体、主动引劫、以雷炼身 | 三大机制全部解锁，难度爬升 |
| 终局 | **破立期** Breaking & Ascending | 功法大成，引动史无前例终极紫雷劫池，凡骨碎裂、白日飞升 | 终极天劫 = 综合考验，通关 |

失败/分支态（详见叙事文档）：凡人暴毙（丹毒满/被雷劈死/饿死灾年）、走火入魔、低阶飞升等多种结局与 Game Over 叙事。

## 5. 三大核心机制概述（详见 docs/05–07）

1. **天劫倒计时 + 避雷针阵法塔防** (`05-mechanic-tribulation.md`)
   - 体魄与准备度达到阈值 → 玩家可主动引劫；拖延过久则因天道因果账触发催讨式天劫。
   - 归零 → **塔防生存模式**：天雷随机劈向农田/居所。
   - 平时布设「引雷阵 / 绝缘阵」（金属性灵草作避雷针、地形绝缘）保护核心区。
   - **劫雷淬体**：被劈中 = 大幅掉血 + 肉身淬炼 Buff；需精准控血「扛几雷但不死」推进功法。

2. **凡骨丹毒 + 药性相克的非线性炼丹** (`06-mechanic-alchemy.md`)
   - 无灵根 → 生食灵草不吸收反积「丹毒」，丹毒满暴毙；必须炼丹中和。
   - 灵草带 寒/热/温/平 药性标签；丹炉槽位系统实时监控「火候」与「药性平衡条」。
   - 寒热极端冲突 → **炸炉**；完美中和 → 出「避雷丹/生骨丹」等特定抗劫丹药。
   - 非线性：同一组材料在不同火候/顺序下产出不同结果（涌现配方）。

3. **动态因果 + 天象奇遇（有喜有悲）** (`07-mechanic-celestial-events.md`)
   - 凡人无法改大势，但大环境波动直接打击小农庄。
   - 底层权重算法周期触发「天象大事件」：天骄降世(喜)、灵气枯竭/灾年(悲)、魔修过境(危与机) 等。
   - 每事件带因果链（如灵气潮汐→灵草翻倍成熟→引来妖兽→连夜守田）。

## 7. 设计原则与硬约束 (Constraints)

- **C1 纯代码无引擎**：不使用 Unity / Cocos / Unreal / Godot 等通用引擎；允许使用底层库（渲染/输入/音频/打包）。架构必须为「自研薄引擎层 + 数据驱动内容」。
- **C2 Vibe-Coding 友好**：模块边界清晰、单一职责、高可测、低隐式状态；AI 可逐模块生成与验证。避免魔法全局、避免隐式时序耦合。
- **C3 确定性与可复现**：核心模拟使用可注入的 PRNG（种子化）；天象/天雷/炸炉等随机事件都可由种子复现，便于测试与回放。
- **C4 可自动化测试**：业务逻辑与渲染解耦；存在无头 (headless) 模拟入口；平衡可通过蒙特卡洛/参数扫描自动调参；CI 可跑。
- **C5 凡人挣扎感**：数值上玩家始终弱小，资源稀缺，死亡真实；但提供学习曲线与"可挽回的局部失败"。
- **C6 数据驱动内容**：灵草/丹方/奇遇/物品/事件均为声明式数据表（JSON/TS 数据），策划与 AI 可不改代码即扩展。
- **C7 美学统一**：极简/程序化美术优先，限定调色板；音频服务于"慢→急"的情绪曲线。
- **C8 全程中文（面向国内市场）**：游戏内一切可见文本（UI/对话/教程/菜单/物品名/事件文案/结局）默认 **zh-CN 中文**；架构须含 **i18n 键值层**（字符串不入码，便于未来扩展他语）+ **内置 CJK 字体**（开源 霞鹜文楷 / 思源系列）+ **中文输入法(IME)合成支持**。工程方案见 `10-technical-architecture.md §13`。
- **C9 优先开源**：代码/字体/内容以开源协议优先发布（面向国内市场建立社区与口碑）；仅当市场广泛好评后再考虑付费版本/DLC。许可选型见 `20` D-24。

## 9. 阅读对象与使用方式

- **本次（调研阶段）读者**：项目所有者（你）。阅读本基线确认方向；其余文档为深挖产出。
- **Vibe Coding 阶段读者**：AI 编码 agent。按 `00-README.md` 的执行手册，从 `10/11/12` 建工程骨架，再按 `05–09` 实现机制，用 `14–17` 校准数值与测试。
- **任何文档改动**：若改动会违反本基线（核心循环/术语/约束），须先修订本文件，再做下游同步。
