### R-DESIGN-01 失败时的转向选项

若 M3 MVP 验证"不好玩"，按代价递增：
1. **调参级**：调 targeting/控血/炼丹权重，不改机制。
2. **机制级**：某一机制换核（如天劫从塔防改为回合制）。
3. **范围级**：砍一机制，做双机制游戏。
4. **方向级**：重新评估品类组合——最坏情况，但 M3 前置就是为了避免做完才发现。

### Q1 · 死亡模型：Roguelite vs 存档？ ✅ 已裁定（D-03）

| 选项 | 说明 |
|------|------|
| A. 纯 Roguelite（permadeath + 重开） | 死即重开，仅保留 meta 解锁 |
| B. 纯存档（可 scum） | 随时存读，死亡可回滚 |
| **C. 混合制（推荐）** | 死亡损失流动资产（修为/丹药/材料 50%），保留知识资产（残卷/阶段/已解锁丹方） |

**推荐：C**。理由：
- 本游戏单局 18–25h，A（纯重开）惩罚过重劝退；B（纯 scum）让死亡无意义，破坏 Pillar 1（凡人脆弱）。
- C 在 `16` §7 已展开：死亡是"泄压阀"（清通胀）+ "学习曲线不归零"（知识保留鼓励再试）。proxy"再来一次 ≥ 70%"在此模型下可达。
- 与 C5"可挽回的局部失败"一致。

> **裁定（`20` D-03）**：采纳 **混合制 C**：死亡损失 50% 流动资产（修为/丹药/材料），保留知识资产（残卷/阶段/已解锁丹方），不回档、不允许 save-scum；roguelite meta 默认关。该模型让死亡成为通胀泄压阀，同时学习曲线不归零。

**影响**：M6（死亡经济落地）；`16` §7 须按 D-03 微调。

### Q2 · 交易系统：常规商店 vs 事件交易 vs 无？ ✅ 已裁定（`20` §4 / D-22 倾向）

| 选项 | 说明 |
|------|------|
| A. 常规商店（开放经济） | 随时买卖 |
| **B. 仅事件交易（推荐）** | 仅游方散仙事件触发，库存随机有限 |
| C. 完全无交易 | 纯自给自足 |

**推荐：B**。理由：
- A 开放经济 = 可 farm 灵草换钱买丹，闭环打开即失衡，违背 C5。
- C 过严，切断"舔包战利品变现"这条乐趣线，且战利品失去意义。
- B（`16` §5）保留交易乐趣但严控规模：散仙稀有、库存随机、价格随 stage 涨。最小可行经济。

**影响**：M4（散仙事件落地）。**urgency：低**（不影响 M0–M3）。

### Q3 · 难度目标锚点：首劫死亡率定多少？ ✅ 已裁定（`20` §4 / D-23 倾向）

> **裁定**：首劫存活率锚定 **60–75%**（即死亡率 25–40%），落在本推荐 B 区间（55–65% 存活）的偏宽容侧。`14` §8.1 / `17` §5.3 已据此更新。

| 选项 | 首劫菜鸟死亡率 |
|------|----------------|
| A. 激进（建立强敬畏） | 40–50% |
| **B. 平衡（推荐）** | 35–45%（`17` §5.3 取 rookie 存活 55–65%） |
| C. 温和（不劝退） | 20–30% |

**推荐：B**。理由：
- `14` §10 锚点"前 3 场天劫菜鸟死亡率 ≈ 30%"。此处细化首劫 35–45%。
- A 太狠，首劫即劝退大半新玩家；C 太软，"凡人脆弱"叙事不可信。
- B 在"建立敬畏"与"不劝退"间取衡。后续天劫死亡率可升（stage3 菜鸟死亡 65–75%）。

**影响**：M3 调参目标 O1（`17` §6.1）。**urgency：高**（M3 前必须定，否则调参无目标）。

### Q4 · 最终语言 / 技术栈？ ✅ 已裁定（D-02 / D-25）

> **裁定**：技术栈采用 **TypeScript(strict) + PixiJS v8 + Electron + Vitest/fast-check + Zod + Web Audio**；游戏可见文本全程 zh-CN，含 i18n 键值层、内置 CJK 字体与 IME 支持。下文保留原始选项供追溯。

| 选项 | 说明 |
|------|------|
| A. TypeScript + 自研薄引擎 + Canvas/WebGL | 类型安全、生态、harness 友好 |
| B. Rust + 宏/wasm + 自研 | 性能/确定性更强，但开发慢 |
| **C. TypeScript 优先（推荐）** | sim 用 TS（纯函数易测），渲染层 Canvas2D 起步可换 WebGL |

**推荐：C**。理由：
- Vibe Coding 范式下，AI 写 TS 的可靠性 >> Rust；类型系统 + PBT 天然适配。
- sim/render 分层（C4）下，性能瓶颈只在天劫期（R-TECH-02 可优化），不必全栈 Rust。
- 确定性（C3）靠注入 rng + 定点运算即可，不依赖语言。
- 若 M3 性能不达标，可只把热路径（雷 targeting/伤害）用 wasm 加速，不整体迁移。

**影响**：M0（`10-technical-architecture.md`/`12-project-structure.md`）。**状态：已定**。

### Q5 · 付费 vs 开源？ ✅ 已裁定（`20` D-24 = 优先开源）

> **裁定**：**优先开源**。代码 MIT/Apache-2.0、字体 OFL（霞鹜文楷/思源）、内容 CC-BY 4.0；市场广泛好评后再考虑付费正式版/DLC。面向国内市场，开源更利于建立社区与口碑。

| 选项 | 说明 |
|------|------|
| **A. 优先开源（采用）** | 代码 MIT + 字体 OFL + 内容 CC-BY；免费发布 + 可选赞助；好评后再付费 |
| B. 商业付费（Steam 等） | 需美术/音频/营销投入；推迟到市场验证后 |
| C. 暂缓 | ~~原推荐~~（已被用户指令取代） |

**理由**：用户明确"优先开源，好评后再付费"；开源不阻塞未来商业化（可双轨：开源核心 + 付费 DLC/美术）。许可证在 M0 即写入 `LICENSE`（C9）。

**影响**：M0（写入 LICENSE + 字体/内容许可合规）；M6（发布形态）。**urgency：低**（不阻塞机制开发）。

### Q6 · 美术风格基调？ ✅ 已裁定（`20` §4 倾向，与本推荐 C 同向）

> **裁定**：程序化优先 + 极简水墨占位（C7），与本推荐 C（水墨/丹青程序化）一致。详细落地见 `13-asset-art-audio.md`。

| 选项 | 说明 |
|------|------|
| A. 极简几何 + 调色板（最省） | 色块/线条，靠动效与音效补 |
| B. 像素艺术（中等） | 风格统一但工作量中等 |
| **C. 水墨/丹青程序化（推荐）** | 限定调色板 + 程序化笔触 + 留白（C7） |

**推荐：C**。理由：
- C 直接服务 Pillar 5（东方仙侠美学与留白），与"凡人挣扎"的苍凉基调契合。
- 程序化美术降低产能压力（R-CONTENT-01），适配纯代码无引擎（C1）。
- A 太干瘪缺仙气；B 像素与水墨调性冲突。
- 雷劫瞬间可强化视听冲击（Pillar 3 慢→急）。
