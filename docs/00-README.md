## 2. 一键速览（待各文档落地后回填最终值）

- **游戏**：2D 修仙种田 + 炼丹解谜 + 天劫承雷生存；纯代码、不依赖通用引擎。
- **核心循环**：种田 → 炼丹 → 天劫倒计时 → 引雷承体(阵法控伤) → 淬体突破 → 下一阶段 → … → 终极紫雷劫 → 飞升(通关)。
- **三大创新机制**：① 天劫倒计时 + 引雷阵法控伤 + 劫雷淬体控血；② 凡骨丹毒 + 寒热温平药性相克的非线性炼丹（基于中医七情配伍：相杀→净毒、相反→炸炉、相须→增效）；③ 动态因果天象奇遇引擎（喜/悲/危/机）。
- **关键设计支柱**：凡人脆弱、偷天快感、慢/快张力、系统涌现、东方仙侠美学、可自动化验证。
- **推荐技术栈**：见 `10-technical-architecture.md`（倾向：TypeScript + Canvas/WebGL + 轻量 ECS（如 bitECS）+ 固定步长游戏循环 + 数据驱动 JSON 内容；理由：Vibe-Coding 友好、自动化测试成熟、确定性可控、分发容易）。
- **语言与发行**：**全程中文（zh-CN）**，面向国内市场（`00` C8 / `20` D-25，i18n+CJK 字体+IME 方案见 `10` §13）；**优先开源**（`00` C9 / `20` D-24），市场广泛好评后再考虑付费。

## 4. Vibe Coding 执行手册（核心：怎么从设计包造出游戏）

### 4.1 前置：先立工程地基（对应 `12` + `10` + `17`）

1. **初始化仓库**：按 `12-project-structure.md` 目录树建 `src/sim`(纯逻辑) / `src/render`(表现) / `src/content`(数据) / `src/io`(持久化) / `tests/` / `tools/`。**逻辑层零渲染依赖**（C4）。
2. **立确定性骨架**：固定步长游戏循环（fixed-timestep + accumulator）+ 可注入种子化 PRNG（多 stream：`lightningStream`/`eventStream`/`growthStream`…）+ **记录输入而非状态**的回放基建。这是后续一切自动化测试的地基（见 `17`）。
3. **立测试基建**：单元测试框架 + 属性测试（fast-check 式）+ 黄金回放（golden schedule：固定种子+输入流→断言快照）+ 无头模拟 runner。**M0 的退出标准就是"能跑 1000 局种子化无头对局并产出统计"**（`18` 的 M0）。
4. **立内容管线**：JSON/TS 数据表 + schema 校验（防脏数据）+ 热重载。灵草/丹方/奇遇/物品全部数据驱动（C6）。

> **关键纪律**：在写任何"好玩的内容"之前，先把"可被自动验证"的骨架搭好。否则后期无法零干预调平衡。

### 4.2 开发顺序（垂直切片优先，对应 `18`）

按里程碑推进，每个里程碑是**端到端可玩+可测**的垂直切片：

- **M0 工程骨架**：分层 + 游戏循环 + 无头测试 + 内容管线（上节）。
- **M1 序章教程**：凡间作物种田（教基础操作+时间）。→ 验证：种田/时间/存档。
- **M2 第一幕**：储物戒 + 灵草（灵气生长）+ 炼丹（药性/火候）+ 丹毒。→ 验证：生长公式、药性数学、丹毒模型。
- **M3 核心循环**：天劫倒计时 + 雷场承劫 + 劫雷淬体 + 突破进阶。→ 验证：targeting 权重、控血甜区、阶段曲线。**最高风险项，最早验证"好不好玩"。**
- **M4 天象引擎**：动态因果事件。→ 验证：事件权重/因果链/玩家应对空间。
- **M5 终局**：终极紫雷劫 + 飞升结局。→ 验证：通关可达性。
- **M6 打磨**：平衡自动调参、音频美术、可访问性、juice。

### 4.3 每个"AI 开发单元"的标准动作（单一系统的端到端增量）

当 AI 要新增/改动一个系统（如"加一种新丹药"或"调天雷 targeting"），按此闭环：

```
1. 改内容数据表(content/*.json) + 必要时改 schema   ← 数据驱动优先(C6)
2. 写/改 sim 层纯函数(逻辑, 无渲染无IO)              ← 单一职责(C2)
3. 写单元测试 + 属性测试(不变式)                      ← 纯函数易测
4. 写集成测试(一个完整周期: 如一次炼丹/一次天劫)      ← 黄金回放
5. 跑无头模拟(种子化批量), 看统计是否在目标区间        ← 蒙特卡洛(17)
6. 若越界: 查参数注册表(14)→调参→重跑→回归            ← 自动调参闭环
7. (最后)接表现层渲染/UI, 跑视觉回归 snapshot          ← 表现层最后接
```

- **失败即阻塞**：任一步红，AI 不得标记完成（无假完成）。模拟越界=平衡 bug，须调参或修逻辑。
- **表现层最后**：先让"逻辑对"，再让"看着对"。逻辑层可在无 GPU 环境全程验证。

### 4.4 内容扩展（不改代码）

- 新灵草/丹方/奇遇/物品：只改 `content/` 数据表 + 过 schema 校验，无需碰 sim 代码（C6）。
- 新数值：改 `14-...md` 参数注册表对应的配置项，无头模拟自动回归。

## 5. 零干预自动化开发与调试 SOP（兑现"全程不需要人为干预"）

### 5.1 确定性三原则（一切自动化的前提，C3）

1. **固定步长**：模拟永远看不到可变 `dt`；update 以固定步长推进（如 1/30s 或 1/60s）。
2. **种子化 RNG + 分流**：所有随机走可注入 PRNG，按系统分 stream（局部调参不破坏全局可复现）。禁止 `Math.random()/Date.now()` 进入模拟。
3. **记录输入而非状态**：回放 = 同种子 + 同输入流 → 同结果。存档可存"种子+输入+关键检查点"以省空间。

### 5.2 测试金字塔（对应 `17`）

```
            /\
           /  \  视觉回归(snapshot, 表现层)
          /----\
         /      \ 无头模拟(种子化批量对局, 蒙特卡洛统计)
        /--------\
       /          \ 集成(完整周期: 日/炼丹/天劫, 黄金回放)
      /------------\
     /              \ 单元+属性(纯函数不变式, 最多)
    /----------------\
```

- **单元/属性**：药性向量运算、生长公式、targeting 权重、丹毒模型、存档往返——纯函数，秒级跑数千用例。
- **黄金回放**：固定种子+输入的黄金 schedule，CI 比对快照，任何不确定性漂移立刻红。
- **无头模拟**：成千上万局对局，产出存活率/阶段分布/经济指标分布。

### 5.3 蒙特卡洛平衡自动调参（对应 `14` 参数注册表 + `17`）

1. **定义目标函数**（代理"好玩"）：如"首劫存活率 60–75%"、"平均通关 15–25 小时"、"第 N 天存丹量在 [a,b]"。
2. **参数空间**：`14-...md` 的【平衡参数注册表】即搜索空间。
3. **搜索**：网格扫描 / 随机搜索 / 进化算法（多目标，参考 Volz 2016），每评估=一批无头对局。
4. **策略 bot 分层**（Stratabots 式，Horn 2018）：菜鸟/普通/老练三类自动玩家，发现难度死角（如普通玩家卡死、老练玩家无损）。
5. **输出**：一组满足目标区间的推荐参数 + 各参数敏感度报告，回填 `14`。

### 5.4 自动化调试闭环（失败如何自定位自修复）

```
CI/模拟失败(某个种子/某条对局)
   │
   ▼
取出失败种子+输入流 → 黄金回放定位到具体 tick/系统
   │
   ▼
对照参数注册表与公式 → 判定是"逻辑bug"还是"平衡越界"
   ├─ 逻辑bug → 改 sim 纯函数 → 跑该种子回归 → 全量回归
   └─ 平衡越界 → 自动调参(5.3) → 回归
   │
   ▼
全绿 → 提交; 仍红 → 升级到下一层诊断(记录到 19 风险表)
```

- **可复现=可调试**：任何失败都能用种子+输入流在本地/CI 精确复现，AI 据此定位修复，无需人类重现。
- **CI 门禁**：lint → typecheck → unit → integration → 无头模拟(采样) → 平衡回归(关键指标阈值) → 确定性黄金回放。任一红则阻塞。

### 5.5 必须人类一次性拍板的事项（护栏，对应 `19`）

自动化不能替你决定"想要什么"。这些须由你拍板后，AI 才能全程自动执行（清单见 `19-risk-register.md`）：

1. **最终技术栈**（语言/渲染/ECS）—— 推荐 TypeScript，见 `10`。
2. **存档哲学**：roguelite 永久损失 vs 自由存档 —— 影响"凡人脆弱感"的强度，见 `09/19`。
3. **难度目标曲线**：首劫死亡率、通关时长等代理指标的目标区间，见 `14/17`。
4. **交易/货币系统**：是否保留"游方散仙偶至"的最小交易，还是纯自给，见 `16`。
5. **范围边界**：MVP 切片包含/排除什么，见 `18`。
6. **美术方向**：纯程序化 vs 引入手绘资产，见 `13`。

> 拍板后写入下方决策日志，AI 据此零干预推进；过程中若出现新的"必须人类决定"项，记入 `19` 并暂停该处等你定夺。
