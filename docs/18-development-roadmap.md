# 18 · 开发路线图（Development Roadmap）

> 本文件定义《Aeon Vale》从空仓库到飞升结局的**里程碑序列**、每阶段的**垂直切片**、**退出标准**与**风险前置**策略。
> 它服务于"Vibe Coding + 全程无人为干预"范式：每个里程碑都必须能被 `17-testing-and-automation.md` 的 harness 自动验证，否则不算完成。
> 工作量以**理想人日 (ideal dev-day, idd)** 估算，假设 AI 辅助编码、人工仅做方向决策与抽检。粗估 ±50%，勿当承诺。

## 当前推进焦点

> 2026-07 调整：本项目当前首先是**作品集导向的纯代码离线单机演示**，但这只是阶段性开发策略，不是项目的最终天花板定义。
> 当前执行层优先级仍为 `MVP 必要项 -> Patch 候选 -> DLC/TODO`，先用最小可玩且足够惊艳的切片证明方向成立，再继续把项目逐步推进为可长期迭代的独立游戏作品。
> 判断标准不再是“系统越多越好”，而是“是否稳定、是否可验证、是否足以体现纯代码方案的控制力与独特性，并能为后续桌面端发布与持续扩展打下可靠底座”。

### 平台与版本策略

- **当前体验形态**：浏览器版。用途是本地开发、自动化回归、GitHub Pages 展示与作品集传播；它是现阶段入口，不是项目终态平台定义。
- **近期正式目标**：离线单机桌面端封装，优先 `Windows` 与 `Linux`；浏览器版继续保留为试玩/展示入口，并与桌面版共用同一套离线核心。
- **远期探索形态**：`Android` 等移动端仅作为后续阶段评估项，不进入当前 MVP 或近期 Patch 阻塞链路。
- **硬约束**：所有核心玩法、存档、输入、世界推进都必须先满足“可本地离线运行、可浏览器运行、可桌面封装”的共同子集，不允许依赖后端、联机同步或在线裁定。

### 长期目标分层

- **第一阶段**：作品集 MVP。目标是稳定、顺手、可复现、能体现纯代码实现力。
- **第二阶段**：独立游戏首版。把 MVP 中最有说服力的农务、阵法、修炼与日循环扩成真正可持续游玩的离线单机版本。
- **第三阶段**：以 `Patch / DLC / 大版本` 方式补深内容，逐步向《星露谷物语》的长期生活感靠近，同时吸收《鬼谷八荒》《觅长生》《了不起的修仙模拟器》《太吾绘卷》等修仙竞品在成长、经营、关系与世界反馈层面的长处。

### 自动化执行法（OMC / GSD / ECC 对齐）

- **OMC 对齐**：把每一轮工作都压成“可诊断、可回归、可暂停”的窄切片，优先处理会破坏首轮体验、输入一致性、存档可靠性和演示稳定性的故障或缺口。
- **GSD 对齐**：开发顺序按 `MVP 必要项 -> Patch 候选 -> DLC / TODO` 分波推进；每一波都要求先明确退出标准，再落代码、补测试、跑门禁，不以“已经写了很多系统”替代完成判定。
- **ECC 对齐**：把 skill 当成工程纪律来源而不是噱头；核心要求是把规则固定进仓库文档、测试和脚本里，让后续自动化开发即使无人监管也能沿同一套优先级持续推进。

### 当前分级执行表

| 级别 | 当前目标 | 本阶段只做什么 | 明确不做什么 |
|------|----------|----------------|--------------|
| `P0 / MVP 必要项` | 做出 10~15 分钟稳定、顺手、足够惊艳的首轮演示 | 新手日循环、输入一致性、日终反馈、基础存读档、首批 showcase 系统 polish、门禁长期全绿 | 横向加新玩法、大体量叙事尾盘、联网、多平台专用分支逻辑 |
| `P1 / Patch 候选` | 在首版可展示后补强体验与分发能力 | Windows/Linux 桌面封装、桌面发布脚本、交互细修、暖棚/阵法日常深化、少量高频生活层 | 为了桌面端重写核心 sim、恢复服务器依赖 |
| `P2 / DLC / TODO` | 长线追近《星露谷物语》与修仙竞品厚度 | 更深关系线、后终局生活层、更多事件池、更多经营线、移动端适配 | 在作品集首版开发期直接并入主阻塞链 |

### 当前 P0 施工顺序

1. 首轮日循环顺滑度：确保“整地、播种、浇水、收获、出货、过夜、补种、再播种”全程低摩擦。
2. 高层 UI 输入边界：任何目录、面板、模态都不能把同次输入漏到底层世界动作。
3. 日终/次日反馈：让玩家明确知道“今天卖了什么、赚了多少、明天该做什么”。
4. Showcase 系统抛光：优先保留一到两个最能代表纯代码优势的跨日系统，当前优先 `阵法护田` 与 `暖棚经营`。
5. 浏览器展示稳定性：持续补齐 unit/integration/browser 回归，避免作品集演示翻车。

### 分级自动开发执行规程（OMC / GSD / ECC）

> 本节把“按优先级自动推进”落成仓库内的执行规则，供后续 Agent 在无人监管下按同一口径持续开发。

#### OMC 切片约束

- 每一轮只允许处理一个可验证主切口：`输入边界 / 日循环反馈 / 高频预览链 / 存读档稳定性 / showcase 系统 polish / 桌面封装准备` 之一。
- 每一轮改动都必须回答三件事：
  1. 它属于 `P0 / P1 / P2` 哪一级。
  2. 它服务的是哪一条真实玩家高频路径。
  3. 对应门禁与测试如何证明它没有把首轮演示打断。
- 若某提案同时触及多个系统、多个长期内容面或需要新增大量状态模型，默认降级，不进入当前切口。

#### GSD 波次执行表

| 波次 | 对应级别 | 目标 | 允许推进内容 | 完成判定 |
|------|----------|------|--------------|----------|
| `Wave A` | `P0 / MVP 必要项` | 稳住首轮 10~15 分钟演示 | 新手农务闭环、高层输入边界、日终/次日反馈、高频界面读图、美术接入、浏览器稳定性 | `pnpm governance:check` / `typecheck` / `test` / `build` 全绿，且首轮核心路径更清晰 |
| `Wave B` | `P1 / Patch 候选` | 首版之后补体验与分发 | Windows/Linux 封装、发布脚本、少量高频生活层、暖棚/阵法深化、桌面交互细修 | 不反向破坏浏览器与离线同核前提，且不引入联网依赖 |
| `Wave C` | `P2 / DLC / TODO` | 长线补深 | 更深关系线、后终局生活层、更多事件池、更多经营线、移动端评估 | 必须建立在 `Wave A/B` 稳定完成之后，且不回流阻塞首版 |

#### ECC 落地口径

- **文档先行**：每次波次调整、优先级迁移、平台口径修订，都先更新仓库文档，再改代码，避免后续 Agent 沿旧假设继续扩写。
- **规则固化**：优先让测试、脚本、helper 和 manifest 反映新的执行口径，而不是只在对话里声明策略。
- **技能使用方式**：skill 的价值在于固定工程纪律，而不是替代验收；任何 skill 导出的建议都必须最终落到仓库文件、测试或脚本上。

#### 自动推进停手条件

- 遇到以下情况必须停止当前波次扩写，并把需求降级到下一层：
  - 需要新增联网、后端、账号、云同步或任何远端裁定依赖。
  - 需要为“更像完整大作”而大幅扩展系统广度。
  - 现有门禁无法证明改动安全，且短期内不能补上最小覆盖测试。
  - 为接入资产而反向虚构新的系统状态、NPC 身份或地点机制。

#### 当前自动推进推荐顺序

1. `Wave A / P0`：继续压高频可见表层，优先“总览 -> 面板 -> toast -> 世界层”这条读图链。
2. `Wave A / P0`：继续修输入/结束一天/模态/目录的意图边界，保持首轮演示稳定。
3. `Wave A / P0`：把已入库美术继续挂到真实高频链路，不扩内容系统。
4. `Wave B / P1`：在 `Wave A` 稳后，再推进桌面封装与分发脚本。
5. `Wave C / P2`：所有厚内容开发一律后置，不抢占当前主阻塞链。

#### MVP 必要项

- 单机离线完整可运行，不依赖账号、联网、服务器、云同步。
- 启动、输入、存档、读档、结束一天等基础循环稳定。
- 至少一条完整且可重复游玩的农务日循环。
- 输入骨架统一：移动、主确认、副取消、菜单入口、地点目录、热栏切换不互相穿透。
- 仓库门槛必须可持续通过：`pnpm governance:check`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- 至少保留一项能明显体现“纯代码按需实现”优势的 showcase 系统，优先为 `暖棚经营` 或 `阵法护田` 这类可验证、可演示、可解释的跨日系统。

#### Patch 候选

- 在 MVP 稳定后继续增强体验，但不会阻塞作品集首版交付的系统。
- 典型内容包括：
  - 桌面端封装链路、桌面适配输入与发布脚本。
  - 暖棚经营更高阶层级与更细经营曲线。
  - 阵法农庄化的更多分工。
  - 留世后的少量高频日常入口与低摩擦生活层。
  - 少量必要的 UI polish、浏览器/桌面交互回归补强、提示文案与反馈优化。
  - 基于 GitHub Actions 的桌面构建与发布准备，但前提仍是同一套离线单机核心先在本地与浏览器演示稳定。

#### DLC / TODO

- 当前版本明确降级、不继续主动扩写的方向：
  - 更大规模 NPC 社交尾盘。
  - 收藏线、图鉴、博物馆式长期完成度。
  - 巡守兽深度成长矩阵与大量协防扩写。
  - 大体量后终局生活内容、更多事件池、更多经济线。
  - Android 等移动端专门适配工程。
  - 任意联机/联网/账号/后端/云存档/排行榜相关能力。

#### 离线单机平台口径

- 浏览器版是**开发、测试、公开展示与试玩入口**，不是产品终态的平台限制。
- Windows / Linux 桌面封装是当前最近的正式游玩目标；后续所有输入、资源、存档与发布链设计，都应优先考虑这一路径可持续落地。
- Android 与其他移动端保持后置评估，不进入当前 `P0 / P1` 阻塞链。
- 任何联机、联网、远端配置、在线活动、服务器裁定、账号体系、云存档、排行榜或需要常驻后端的提案，都不进入当前开发主线；若出现相关占位，应暂停并降级到未来另行评估。

### 本轮执行结论

- `P1-2 输入与操作流继续向《星露谷物语》对齐` 仍是当前 **MVP 必要项**，因为它直接决定项目是否“可玩、顺手、稳定”。
- 已落地的低摩擦切片：
  - 留世日常快捷入口：`Alt+Q` 镇守告示、`Alt+W` 旧茶棚、`Alt+E` 暖棚。
  - 农庄操作入口收束：`Shift+M` 呼出农庄操作，`数字 1-0` 直达对应子项。
  - 地点服务入口收束：地点选择激活后，`数字 1-0` 直达当前地点服务，`空格/E/回车` 均可确认进入。
  - 地点目录在高层上下文中优先吞掉同次世界动作输入，避免菜单打开时按键直接穿透到底层农务。
- 近期开发约束：
  - 不再继续横向扩展系统总量。
  - 优先修稳定性、输入一致性、存档可靠性、展示系统 polish。
  - 其余增强项一律先降级到 Patch 或 DLC/TODO，再决定是否继续开发。

### 最近已补齐的 P0 稳定性切片

- 菜单/总览高层 UI 与底层农务输入已做隔离：库存、体修总览打开时，不再把同次按键或左键确认穿透到底层世界动作。
- 高层遮罩下的“结束一天”意图也已被锁住：库存、体修总览打开时，`Enter` 不会误推进到次日，必须先显式关闭遮罩后才会恢复日终语义。
- 暂停态也纳入同一条显式意图规则：暂停期间 `Enter` 不会误推进到次日，必须先恢复行动后才重新启用日终输入。
- 业务型交互面板也继续向同一规则收束：仓储等面板打开时，`Enter` 保持面板确认语义，不会漂回“结束一天”；只有退出面板后才恢复日终输入。
- 叙事/对白模态也补上显式回归约束：剧情弹窗打开时，`Enter` 只推进当前对白并标记已见，不会顺手把当天直接推进到次日；只有对白关闭后才恢复日终语义。
- 终局抉择模态也按同样标准锁住显式意图：飞升二选一打开时，`Enter` 不会代替玩家做决定、也不会误触发其他推进；只有 `1/2` 这类明确选择键才会改写结局状态。
- 地点目录本身也补上日终边界回归：目录打开时，`Enter` 维持地点/服务确认语义或无副作用预览语义，不会漂回“结束一天”；只有显式退出目录后才恢复日终输入。
- 热栏滚轮在高层上下文中的阻断也继续补证：体修总览打开时，滚轮不会偷偷改掉当前工具槽位，必须先退出总览后才恢复热栏切换。
- 同类约束也扩到业务交互面板：仓储等面板打开时，滚轮不会把当前工具槽位切走，避免面板关闭后的同次世界动作落到错误工具上。
- 叙事对白模态下的热栏滚轮也补上显式回归：剧情弹窗打开时，滚轮不会偷切工具槽位，避免玩家确认对白后下一次世界动作落到错误工具。
- 终局飞升抉择模态的热栏滚轮也已锁住：二选一弹窗打开时，滚轮不会改动当前工具槽位，也不会替代玩家做结局选择；只有 `1/2` 这类显式输入才会推进终局分支。
- HUD 帮助提示已按作品集首版分级收束：默认首屏只展示 `MVP 必要项` 的核心操作，地点目录、农庄面板、对白、飞升抉择等高层上下文再按需切换到对应提示，不再把 Patch/DLC/旧兼容键一次性摊在首屏上制造庞杂感。
- 新开局默认物资已收窄回首轮农务闭环：只保留少量 `mossling/dewroot` 种子、对应低阶药草、基础农具与极少量灵石，不再在第一分钟直接暴露高阶种子、试验药材与堆肥/交易链启动包，避免作品集首版出现“系统很多但主线体验失焦”的观感。
- 地点目录也已按作品集首版重新分层：主目录优先只保留当天真正构成日循环的可操作动线（农庄、集市、外出探索、遗迹/残脉），纯叙事挂点与重复功能入口继续存在于世界设定与 NPC 行踪里，但不再作为首会话主目录噪音暴露。
- 新档首轮农务引导已进一步显式化：默认 HUD 帮助下方会按真实状态滚动给出“先翻地 / 再播种 / 再浇水 / 等成熟后收第一株”的当前目标，开场欢迎提示也不再只讲题材口号，而会直接落到第一天可执行动作上。

  - 主动引劫倒计时中的存档恢复后，继续推进与连续推进结果一致。

## 1. MVP 垂直切片定义（在 M3 交付）

> 最小可玩闭环，证明"核心循环好玩"。**这是项目成败的判定局**。

### 1.1 切片包含

```
翻地 → 种 1 种灵草(Frostmarrow) → 灵气生长 → 收获
  → 炼 1 种丹(承雷丹方) → 控火出丹
  → 引 1 次小天劫(stage1, 3 雷)
  → 布设 1 个引雷阵 + 1 个绝缘阵
  → 控血接雷(目标 HP 15%)
  → 扛过 → 看到修为 X 增长 + nearDeathBonus 结算
```

### 1.2 切片排除（严守范围）

| 排除项 | 理由 |
|--------|------|
| 序章叙事/UI 精修 | M1 已做基础；MVP 只需能跑 |
| 多 tier 灵草/丹方 | 只验证 1 条链足够 |
| 天象奇遇 | M4；MVP 用固定无事件 |
| 飞升/终局 | M5 |
| 音频/美术 | 用占位色块 |
| 存档系统 | MVP 用进程内状态（M6 补存档） |
| 交易系统 | 明确不做（`16` §5） |

### 1.3 为何这样切

- **单链纵切**：从翻地到突破，穿透所有三大机制，验证"联动是否产生乐趣"——而非横向铺内容。
- **stage1 only**：最小数值面，但仍含控血曲线（`14` §6.2）这一灵魂机制。
- **可测**：整个切片可被 `rookie`/`normal`/`veteran` bot 跑通，产出通过率（`17` §5.3）。

- [ ] `P2-1` 阵法农庄化：把阵法从渡劫专用扩展到护田、聚灵、控温、驱兽等日常循环。当前首刀已把阵法接入纯离线日终农务：`绝缘阵` 会为覆盖农田保留部分湿度、减轻失养造成的伤苗，`引雷阵` 则会让覆盖范围内的金属性灵草地块获得更高的聚灵回复，使阵法开始真实参与跨日农庄经营，而不再只在渡劫或设施加工时生效；随后又把阵法接进 `妖兽潮 -> 啃食成熟灵草` 的日常风险链，令 `引雷阵` 覆盖的成熟作物更容易成为诱饵田、`绝缘阵` 覆盖的成熟作物会被妖兽后置处理，从而让布阵开始真实改写守田优先级与成熟收割布局；前一刀继续把 `绝缘阵` 的“控温”语义压进留世暖棚日终结算，只要农庄内存在活跃绝缘阵，就会提高当日暖棚养护后的棚温回升，并在失养时提供额外缓冲，且加成强度会随活跃绝缘阵数量分级，令阵法、暖棚与留世经营第一次形成可验证的跨系统控温闭环；最新这一刀则补上首个“驱兽”闭环：当妖兽潮期间田里只剩绝缘阵护住的成熟灵草、且没有引雷阵继续提供诱饵田时，妖兽会在次日直接被驱离而不是继续赖田空耗持续天数，使阵法第一次真实改变妖兽潮的停留时长，而不只是改写啃食优先级。最新又把阵法与巡守兽串成可验证的农庄共振：已固化 `阵守` 专长的巡守兽被指派到活跃阵法覆盖内的地块巡逻时，会放大该阵法自身领域的日终农务收益——绝缘阵覆盖内 `湿度保留 +2`、`作物健康保护 +1`，引雷阵覆盖内金属性灵草 `灵气恢复 +0.05`；阵守精通层（羁绊≥80）收益翻倍（`+4 / +2 / +0.1`）。共振由 `arrayWardenResonanceForTile` 派生判定、无需新持久字段（旧档自动兼容），并以单测覆盖基础/精通两层与“错专长 / 无巡逻 / 无阵法覆盖”三类不触发路径，首次让 `阵法农庄化（P2-1）` 与 `巡守兽养成（P2-2）` 在跨日经营层真正互相增益。最新又把共振从农务收益层延伸到留世控温层：阵守巡守兽在绝缘阵覆盖内巡逻时，除农务收益外，还会额外强化绝缘阵的暖棚日终控温（`careGainBonus / neglectBuffer` 各 +1，精通层 +2），由 `arrayWardenInsulationClimateBoost` 派生判定、与 `insulationClimateControlBonus` 同形叠加，使阵法×巡守×暖棚在跨日经营层形成第二条可验证的控温共振链。剩余仍需继续补更完整的护田分工与更细的驱兽层级。本轮再补引雷阵诱饵田的两层回报与绝缘阵控场稳气：引雷阵覆盖的成熟金属性灵草过熟衰减减半（`farmSystem` 日终），其收获时受天雷淬炼（品质分 +0.12、额外产量 +1，仅在触发时附加事件字段以保持 golden replay 逐字节稳定），绝缘阵覆盖的空地块灵气自然再生亦有微益（+0.08，弱于引雷阵聚灵）；三者均以单测覆盖且无新持久字段。
- [ ] `P2-2` 巡守兽深化与镇守事件联动：让守田兽从单一护田点成长为长期经营伙伴。当前首刀已把巡守兽从“按数量抵消来袭”推进到真实护田策略：在妖兽潮期间，巡守兽会优先拦住将要啃食 `绝缘阵` 覆盖成熟灵草的来袭目标，把外围未巡守地块或 `引雷阵` 诱饵田留给妖兽先吃，并以跨系统回归锁定“阵法护田区 + 巡守兽”联动，不再只是独立数值减伤；随后继续把巡守兽接入留世镇守事件，当轮到 `妖兽侵田痕` 时，有精力的巡守兽可直接出面协防，优先由高羁绊个体承担一次巡守并额外缓解护田压力；上一刀又把 `守田兽哨` 的设计意图压成最小离线规则：新增可持久化的巡逻指派状态与动作，允许玩家把指定巡守兽绑定到单个农田地块，该指派会直接抬高该地块在妖兽潮中的护田优先级，并在 `妖兽侵田痕` 中让已被指派巡逻的个体优先响应；本轮继续补第二个“更多事件协防”切片：当轮到 `残脉阵脚松动` 时，若巡守兽已被指派巡逻且巡逻点落在活跃阵法覆盖内，它也可代为压稳阵脚、免去一次 `破损法宝` 消耗并额外缓解留世压力，从而首次把 `巡逻指派 + 阵法覆盖 + 留世事件` 三条经营链真正串成同一条可验证的离线协防规则；最新一刀再把“长期经营伙伴”落实到确定性养成收益：巡守兽每次成功拦下一只来袭妖兽，或成功协防一次留世镇守事件，都会获得可封顶的羁绊成长，并把成长结果写入事件负载，让护田、巡逻与镇守开始真实反哺长期养成，而不再只能依赖投喂刷羁绊；这一刀继续补第三类事件协防：当轮到 `村镇求援药包` 时，若玩家当日已完成暖棚养护且有巡逻中的巡守兽，它可代为分担一份药包搬运，减少一份药草消耗、额外缓解少量留世压力，并同样获得协防羁绊成长，从而把 `暖棚经营 + 巡逻指派 + 留世事件` 也压成可验证的离线经营联动；最新这刀再把“差异化成长收益”压成可持久化的离线规则：巡守兽新增 `守田 / 阵守 / 递送` 三类专长，占位为空的旧档会自动兼容；当高羁绊个体在真实护田或对应留世协防中成功出手后，会固化专长并写入事件负载，后续分别提高巡逻地块护田优先级、强化 `残脉阵脚松动` 的减压收益、以及强化 `村镇求援药包` 的减压收益，使巡守兽终于不只是在数值上更大，而是开始形成可验证的长期分工。最新这刀把“养成路径与高阶收益”真正压成可验证的精通层：已固化专长且羁绊达 80（`guardBondMax=100` 的高阶区段）的巡守兽进入专长精通态，巡逻地块护田优先级再升一档（守田精通 +4、其余精通 +3），并在 `妖兽侵田痕 / 残脉阵脚松动 / 村镇求援药包` 三类留世协防中分别把专长减压再提升一档（5 / 4 / 3 毫压，高于专长层的 4 / 3 / 2）；精通态由 `guardBeastMasteryReady` 派生判定、无需新持久字段（旧档自动兼容），羁绊跨越阈值或“先涨满后固化专长”的少见路径都会发出 `guard-beast-mastery-unlocked` 事件，并以单测覆盖三条协防链与精通解锁两条路径。最新再补精通层的体力效率收益：专长精通巡守兽日终精力恢复额外 +1/日（高于普通层的固定恢复，`recoverGuardBeasts` 内判定），让长期养成直接转化为更可持续的护田出勤，并以单测覆盖精通/普通两层对比。精通态也被接入留世目标层：新增 `warding-guard-mastery` 镇守目标，按最高羁绊显示进度、出现精通巡守兽即标记完成，让长期养成有明确目标牵引（低优先级，不抢占当日镇守主目标）。剩余仍可继续补更细的专长分化（如第二专长、专长切换）与更高阶的长期养成回报。本轮再补三项养成回报：投喂高阶灵草（tier≥2/≥3）额外提升羁绊（`feedGuardBeast`，+ceil(baseGain/2) 或 +baseGain）；高境界玩家驯养巡守兽自带更高起始羁绊（`(stage-1)×2`，低境界 stage≤1 保持 0）；固化递送专长巡守兽协防留世事件后邻里以灵石酬谢（+1，精通 +2），使递送专长获得区别于守田/阵守的经济身份；均以单测覆盖、无新持久字段。

## 9. 风险前置策略（Risk Front-Loading）

> 最高风险最早验证，避免"做完才发现不好玩"。

| 风险 | 验证里程碑 | 验证方式 | 若失败的应对 |
|------|-----------|----------|--------------|
| **种田即布阵不好玩** | M3 | 人类抽检 + bot 决策多样性 proxy | 调 targeting/阵法权重；最坏重评机制组合 |
| **炼丹非线性无趣** | M2 末 | 涌现配方发现率 bot 测试 | 调 extraction 拱形宽度 P036 |
| **控血不产生张力** | M3 | 险胜率 proxy + veteran 控血使用率 | 调 nearDeathBonus 峰值 P024/区间 P025 |
| **确定性漂移** | M0 | 空壳逐字节相等 | 立刻修，阻断后续 |
| **性能（天劫期实体峰值）** | M3 | 雷击峰值帧率 profile | 降实体数/分帧 |
| **终局劝退** | M5 | normal 通关率 | 调 stage4–5 曲线 |
| **调参过拟合** | M6 | 验证集对照 | 扩 seed 集/降维 |
