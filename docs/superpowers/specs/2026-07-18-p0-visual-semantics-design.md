# P0 视觉语义系统设计

> 状态：设计稿（待实现）  
> 日期：2026-07-18  
> 范围：仅 P0-1、P0-2、P0-3；P0 总门禁通过前不得进入 P1/P2。

## 1. 背景与当前证据

附件要求解决「世界观与视觉的语义断裂」：当前农田主要表现为重复棕色方块，操作目标依赖绿色边框，玩家无法仅凭土地本身理解「种田 = 布防」。

当前仓库已有部分基础，但不足以通过 P0：

- `src/render/palette.ts` 只约束程序化精灵的 16 色索引，没有统一 Pixi UI、世界渲染与 DOM/CSS。
- `src/render/renderer.ts`、`src/render/furnacePanel.ts`、`src/render/worldDecor.ts`、`src/render/characterPresence.ts`、`src/app/main.ts` 和 `src/app/app.css` 仍存在大量颜色字面量。
- 地块已有空地/翻地/播种/浇水状态 helper，但确定性 `first-sow` 截图仍由重复赭色地砖占据，面前格依赖绿色描边。
- 灵气目前主要是青色矩形描边与少量上浮粒子，无法形成「土地下方有流动吞吐」的持续语义。
- 当前渲染顺序为 `tiles Graphics → tileSprites → entities → sceneSprites`。部分画在 `tiles` 上的语义叠层会被后绘制的地砖精灵压住，只能依赖地砖的轻微透明度透出。

因此 P0 不是从零开发，而是把已有零散能力收束成真正可读、可验证的视觉系统。

## 2. 目标与非目标

### 2.1 目标

1. 生产渲染与界面颜色全部来自一个语义颜色模块。
2. 玩家无需文字提示即可区分：可翻耕、已翻耕可播种、不可耕、当前选中。
3. 灵气在农田地表呈现持续、克制的流动呼吸，并随浓度单调增强。
4. 保留低饱和水墨/丹青方向，不引入彩虹色、塑料光效或高饱和霓虹。
5. 用纯 render 状态、确定性数学和自动化截图验证，不触碰 `src/sim` 规则。

### 2.2 非目标

- 不修改农作、生长、导电、天劫或经济数值。
- 不重烘焙整套地砖资产，不改资产清单与校验和。
- P0-3 不写复杂流体 Shader，不引入新渲染依赖。
- 不实现 P1 的三段式成长、肉身面板、常驻倒计时 UI。
- 不实现 P2 的文案重构、神农弹窗或天象罗盘。
- 不以更新视觉基线来掩盖失败；截图必须先通过人眼验收。

## 3. 方案比较

### 方案 A：语义色令牌 + 确定性纹理叠层 + 轻量流线（采用）

- 保留现有地砖与程序化精灵资产。
- 新增统一颜色模块，迁移 Pixi 与 CSS 颜色。
- 在地砖精灵上方增加地表语义层，用细/粗颗粒、明度与遮罩表达土地类别。
- 用单个 Pixi `Graphics` 层绘制低成本正弦流线。

优点：范围可控、易测试、无资产迁移、符合「先有再优」。缺点：最终质感上限低于定制 Shader，但足以完成 P0。

### 方案 B：重新烘焙所有地砖纹理

可获得更稳定的像素纹理，但会扩大脚本、PNG、manifest、checksum 与美术审核范围；选择态和动态灵气仍需额外系统。P0 不采用。

### 方案 C：完整 Tile Shader 管线

可统一噪声、色相和灵气流动，但复杂度、兼容性、性能与截图稳定风险均高，违背附件「初期用最简单线条动画」的纪律。P0 不采用，可作为后续美术升级候选。

## 4. P0-1：全局颜色管理器

### 4.1 单一真源

新增 `src/render/ColorPalette.ts`。只有该文件允许保存生产颜色字面量，并同时提供：

- Pixi 使用的整数颜色。
- CSS 使用的 `R G B` 通道字符串。
- 透明度组合 helper。
- 语义名称，而不是组件或场景名称。

最低必需语义：

- `paper`：宣纸米黄。
- `inkDark`：墨黑/极夜。
- `soilFertile`：肥沃赭土。
- `qiFlow`：灵气青。
- `danger`：朱砂红。

为覆盖现有界面，还需保留克制的扩展族：`ink`、`inkMuted`、`mountain`、`moss`、`gilt`、`loess`、`soilDeep`、`frost`、`ember`、`palePurple`、`moonWhite`、`success`、`warning`、`water`、`shadow` 等。扩展色仍必须落在既有 16–32 色限制内，不按组件随意发明。

### 4.2 与现有资产调色板的关系

`src/render/palette.ts` 保留其「索引 0–15」职责，但每个可见色从 `ColorPalette` 派生，不再重复保存 Hex。这样程序化精灵、Pixi 绘制与 DOM UI 使用同一颜色真源。

### 4.3 CSS 接入

应用启动时调用 `applyColorPaletteCssVariables(document.documentElement)`，写入：

- `--color-<token>`：完整 CSS 色。
- `--rgb-<token>`：仅 RGB 通道，用于 `rgb(var(--rgb-token) / alpha)`。

`app.css` 只能引用这些变量；透明度数值可以留在 CSS，RGB/Hex/HSL 色值不能留在 CSS。

### 4.4 迁移范围

必须迁移以下生产路径中的渲染颜色：

- `src/render/**/*.ts`
- `src/app/**/*.ts`
- `src/app/**/*.css`

不将非颜色算法常量误判为颜色，例如程序化噪声、PRNG 与哈希使用的 `0x6d2b79f5`、`0x7feb352d`、`0x846ca68b`、`0x9e3779b9`。测试、文档、内容文本和二进制资产不在颜色字面量门禁范围内。

### 4.5 自动纪律门

新增单测扫描生产渲染/UI 文件：

- 除 `ColorPalette.ts` 外禁止 `#RGB/#RRGGBB/#RRGGBBAA`。
- 禁止作为渲染色使用的 `0xRRGGBB/0xRRGGBBAA`。
- CSS 禁止硬编码 `rgb()/rgba()/hsl()/hsla()` 色通道。
- CSS 颜色声明禁止 `brown`、`green`、`white` 等命名色；颜色必须使用调色板变量。`currentColor`、`inherit`、`initial`、`unset` 这类继承/控制关键字不视为颜色来源。
- 只允许明确列出的哈希/随机算法常量；allowlist 必须注明用途。

门禁目标不是机械消灭所有十六进制整数，而是保证所有生产视觉颜色都只能从 `ColorPalette` 进入渲染。

## 5. P0-2：地块语义化渲染

### 5.1 分层调整

在 `RenderLayers` 中增加地表语义层，顺序调整为：

1. 地块底层 Graphics。
2. 地砖精灵 `tileSprites`。
3. `terrainSemanticOverlay`：颗粒、翻地暗层、浇水、水纹、选择遮罩。
4. `qiFlow`：灵气流线。
5. 实体 Graphics、作物/角色精灵和其他世界对象。

语义层必须位于地砖精灵上方、作物和角色下方，避免被地砖压住，也避免洗掉作物本体。

### 5.2 纯状态 helper

扩展 `tileVisuals.ts`，由 Tile 推导稳定的地表视觉状态，不在 renderer 内散落条件：

- `surfaceKind`: `tillable | plantable | occupied | blocked`。
- `baseTone`：颜色 token。
- `grainKind`: `fine | coarse | none`。
- `grainDensity`、`grainAlpha`。
- 现有 damp、water sheen、seed、harvest 状态继续保留。

「当前选中」不是 Tile 自身属性，不能从 Tile 单独推导。另设纯 helper：

- `tileSelectionVisualState({ selected, actionable, ambientTimeMs, reducedMotion })`。
- 输出 `selectionMaskAlpha`、`selectionEdgeAlpha` 和呼吸相位。
- `selected` 由玩家位置与朝向计算出的面前格提供；`actionable` 来自现有 readiness helper。
- 未选中时所有输出归零；reduced motion 时 alpha 保留、相位冻结。

### 5.3 土地语义

| 状态 | 视觉规则 | 玩家应读到的意义 |
|---|---|---|
| 可翻耕原地 | 较深赭/黛土，1px 细密颗粒，低对比 | 可以开垦，但尚未整理 |
| 已翻耕可播种 | 更深、更均匀的肥土，短而规整的细纹 | 土已备好，可以播种 |
| 已有作物 | 保持土壤语义，减少中心标记，突出作物阶段 | 当前格已有生命 |
| 不可耕地 | 较浅、去饱和的山黛/灰土，2–3px 粗疏颗粒或断裂纹 | 不可进行农事 |
| 当前选中 | 月白半透明遮罩（目标约 `#FFFFFF20` 的视觉效果）+ 灵气青微光边缘 | 当前操作目标 |

绿色边框必须删除。选择语义不能仅依赖颜色：遮罩、边缘亮度与轻微呼吸同时存在。

### 5.4 降低符号噪声

当前所有可操作地块都会绘制十字、平行线或叉号，导致画面像调试网格。P0-2 调整为：

- 土地可用性由纹理与明度承担。
- 只有面前选中格显示明确操作轮廓。
- 成熟作物保留金色收获辉光。
- 水与供灵保留小型、非颜色唯一的状态符号。
- 不可耕地不再全场画大叉；粗糙纹理已经表达阻断。

### 5.5 确定性颗粒

颗粒由 tile id、坐标和固定盐值生成，不使用 `Math.random()`。同一世界状态、同一画布尺寸必须得到相同颗粒布局，保证回放与截图稳定。不得为每格创建纹理或对象；统一画入一个 Graphics 层。

## 6. P0-3：灵气流动可视化 V1

### 6.1 表现形式

不使用 Shader。为满足「农田下方有微弱动态呼吸线条」：

- 每个有灵气且可耕/已耕地块绘制 1–3 条短流线。
- 流线使用灵气青与月白的低透明组合，沿地表内部缓慢横向或斜向流动。
- 每条线由确定性相位、振幅和方向生成；使用分段折线近似正弦波，不需要贝塞尔或流体模拟。
- 线条位于地砖上方、作物下方，看起来像嵌在土中，而不是漂浮 UI。

### 6.2 数据映射

灵气浓度归一化后必须单调影响：

- 线条数量：低 1、中 2、高 3。
- 线条 alpha：浓度越高越明显，但保持低饱和。
- 线宽：只做小幅变化，避免霓虹。
- 流速：高灵气略快，不能快速闪烁。
- 呼吸幅度：高灵气略高。

低于最低阈值时不画，避免整张地图持续运动。

### 6.3 减少动态效果

当运行设置启用 reduced motion：

- 保留静态灵气纹理和浓度差异。
- 相位冻结，不产生位移或呼吸动画。

### 6.4 性能边界

- 只使用一个 `Graphics` 实例。
- 每帧不创建 Sprite、Texture、Filter 或 Shader。
- 每格最多 3 条、每条最多 6 个线段。
- 仅在世界表面可见且环境帧需要刷新时重画。

## 7. 数据流与边界

```text
Tile / Crop（只读）
        │
        ├── tileVisualState() ───────> 土地语义、照料、成熟状态
        │
        └── qiFlowVisualState() ─────> 数量、alpha、线宽、速度、相位

玩家位置 / 朝向 + readiness
        │
        └── tileSelectionVisualState() -> 遮罩、边缘、呼吸相位
                                               │
ColorPalette ──────────────────────────────────┤
                                               ▼
terrainSemanticOverlay + qiFlow Graphics
                                               │
                                               ▼
地砖之上、作物/角色之下的最终画面
```

`src/sim` 不依赖任何 render 模块；render 只读取已有 tile/crop 数据。

## 8. 测试与验收

### 8.1 P0-1

- `ColorPalette` token 完整、Pixi/CSS 表示一致。
- 16 色索引调色板仍保持长度和像素合法性。
- 颜色纪律扫描通过，生产渲染/UI 不再存在未授权颜色字面量。
- `pnpm typecheck` 与相关单测通过。
- 在迁移前后各保存同一 `first-sow` 确定性关键帧截图；P0-1 截图应证明颜色集中化没有造成意外视觉漂移。完成截图复核后才能开始 P0-2。

### 8.2 P0-2

- 单测覆盖四种地表分类和选择状态。
- 颗粒函数相同输入确定、不同 tile 产生稳定差异。
- Playwright 构造一个同时包含可翻耕、已翻耕、不可耕和选中格的确定性关键帧。
- 截图验收必须证明：不看 HUD 文字也能指出三类土地与当前目标；截图中不存在绿色选择框。
- 桌面 960×542 与移动 736×414 均不因叠层出现裁切或遮挡。

### 8.3 P0-3

- 单测证明浓度增加时线条数量和 alpha 不下降。
- 同一 tile/时间输出确定；不同时间输出变化；reduced motion 时输出静止。
- 浏览器关键帧同时展示低灵气和高灵气地块，高灵气必须肉眼更密、更深。
- 采样两个时间点验证动态线条确实移动，而非静态描边。

### 8.4 P0 总门禁

必须全部满足后才允许进入 P1：

1. P0-1 自动纪律门、类型检查和测试通过。
2. P0-2 人眼截图通过「可耕/不可耕/选中」三项盲读。
3. P0-3 静态截图证明浓度差异，双时间采样证明流动。
4. 相关浏览器关键路径仍可播种、浇水、收获，没有因视觉层改造破坏输入。
5. 保存 before/after 截图作为本地验收证据，但不把生成物加入公开树。

## 9. 实施顺序

严格单线程：

1. P0-1：建立单一颜色真源 → 迁移 → 自动纪律门 → 任务结束截图 → 验收。
2. P0-2：调整分层 → 地表 helper → 纹理/选择态 → 任务结束截图 → 验收。
3. P0-3：流线 helper → Graphics 层 → 动态/无障碍 → 任务结束截图/双时间采样 → 运行验收。
4. P0 总门禁审计。

任一任务未通过时，不提前搭建下一任务的实现。

## 10. 风险与对策

- **迁移量大导致漏色**：用扫描门而不是人工搜索兜底；按文件逐批迁移。
- **语义叠层再次被地砖遮挡**：先调整渲染层顺序，再做视觉参数。
- **颗粒变成视觉噪声**：限制颜色数量和 alpha；可耕细、不可耕粗，不堆更多图标。
- **灵气变成霓虹特效**：限定到灵气青/月白，低 alpha、慢速、小线宽。
- **动态影响光敏或性能**：无闪烁、reduced motion 静止、固定几何上限。
- **截图测试假绿**：自动化只证明状态和画面存在；最终 P0-2/P0-3 仍需查看真实 PNG。
